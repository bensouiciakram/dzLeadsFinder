## What Went Well

- **Correctness spine held.** Every story enforced "the ledger is the source of truth, nothing written on failure": atomic debit (SERIALIZABLE + user-row lock), 30-day re-reveal idempotency, 429/402 full rollback, 409 concurrency mappings (reveal + export), partial-unique-index idempotency. No double-debit reached production semantics.
- **Zero new dependencies.** Hand-rolled xlsx writer (stdlib zipfile), CSV builders, ToastProvider, CSV preview infrastructure — the dependency-halt rule produced better code than pulling libraries.
- **Quota-conscious architecture.** Reveal never refetches search (cache writes + `setQueriesData`), the export preview composes from the search cache (uncached pages only → 0 quota burn for paged-through sets), the ledger CSV fetches all pages only on demand.
- **Snapshot-freeze pattern (4.4/4.6).** Header labels + watermark string frozen into `rows_json` → byte-for-byte download regeneration; copy edits can never change what a paid file renders.
- **Review culture matured.** From epic-1's "fiction status" to real audits with triage discipline (patch / defer / dismiss with rationale); Highs (double-submit drift, CSV formula injection, unvalidated 200, watermark sanitization) caught before merge.
- **Manual-testing loop proved its value.** Unit tests were all green while two user-facing bugs survived (offline hang, table layout) — the checklist caught what jsdom cannot (connectivity state, real layout).
- **Trilingual + RTL discipline.** Every message ×3 locales, Western numerals everywhere (`String()` interpolation), logical properties, `dir="ltr"` content isolation — including catching the `[PENDING REVIEW]` marker that would have shipped inside the actual CSV file for fr/ar users.

## What Needs Improvement

- **Contract-composition slips.** The SERIALIZABLE-under-atomic hazard, the double URL-include W005 namespace collision (4.3), the 4.2 URL scheme that could not reach its own view, the FE type lag for `CompanyResultRow.revealed` — integration slips between contracts, not logic bugs. Repeated across stories.
- **Review findings were found late.** ~69 findings, several Highs, all discovered by review rather than built-in. "Caught in review" is the safety net, not the first line of defense.
- **Cross-stack duplication.** The 5-row export cap, page sizes, and locale sets are triplicated across stacks; parity rests on tests rather than a single source.
- **Tooling friction every story.** PowerShell/UTF-16 sprint-status corruption (4.4), `resolve_customization.py` failing on Python 3.10 (`tomllib`), docker PG16 port conflicts, jsdom blind spots for layout/connectivity.
- **Test blind spots.** Hang/failure paths (offline) and layout were invisible to the suites — the two bugs found only by manual testing.

## Patterns

- **Error-mapping convergence took 3 stories.** Typed exception → HTTP code → localized message → FE state (402/403/404/409/429) was re-derived in 4.2, 4.4, 4.5 before becoming the stable convention.
- **Idempotency/rollback invariants re-litigated.** "Nothing written on failure" was re-asserted in the 4.1, 4.2, 4.4, and 4.6 reviews — each time with new edge cases (concurrent races, timeout-after-commit).
- **User-intent serialization primitive missing.** The reveal in-flight guard (4.2 review) had to be re-invented for export (4.5 review) — a shared "serialize user actions per user" primitive would have saved both.
- **`[PENDING REVIEW]` marker discipline had a real escape.** The fr/ar watermark strings carried the marker into user-delivered FILE content — caught by review; the rule is now scoped (file content never, UI copy flagging convention stays).
