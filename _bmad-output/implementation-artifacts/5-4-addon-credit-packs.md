# Story 5.4: Add-on Credit Packs

Status: done

## Story

As a **heavy user who runs out of monthly credits mid-cycle**,
I want **to buy a one-time add-on credit pack (500 DZD/75 or 1,500 DZD/250) that never expires**,
So that **I can keep working without upgrading my plan**.

## Acceptance Criteria

**Given** the add-on packs
**When** the billing API serves the pack contract
**Then** the server pack table (`PACK_PRICES` in `apps/billing/pricing.py`) exposes both packs — 500 DZD/75 credits (6.7 DZD/credit) and 1,500 DZD/250 credits (6.0 DZD/credit, "Best value") — each with a never-expiry flag and pre-computed unit price, as the data contract the 5.5 PackCards consume on the /billing page [AMENDED 2026-08-10, John PM verdict — the /billing page does not exist in the FE and PackCards is a 5.5 deliverable per the epic index; 5.4 ships the data contracts, 5.5 owns the surfaces; 5.1 F1 precedent]
**And** the pack cards (5.5) render: "Never expires" note with a {colors.success} check icon, unit price in {typography.caption} {colors.muted-foreground}, "Best value" badge on the 250 pack, and a buy button ({colors.primary}) per card — copy contracts recorded in D15 (5.5 consumes)

**Given** a user purchases a pack
**When** a pack checkout is requested via `POST /api/billing/create-checkout/` (the 5.5 PackCards Buy-button handler calls this endpoint)
**Then** the endpoint creates a Chargily checkout with server-side pack metadata (price, credits, description from the `PACK_PRICES` table — client amounts never trusted)
**And** after successful payment, the Celery task grants credits:
- Credit ledger: event_type='pack_grant', pool='pack', amount = 75 or 250
- Balance updates atomically
[AMENDED 2026-08-10, John PM verdict — the click handler is a 5.5 surface; 5.4 owns the endpoint contract; 5.1 F1 precedent]

**Given** the drawdown order
**When** a user with both subscription credits and pack credits makes a reveal
**Then** subscription pool credits are consumed before pack pool credits (subscription-first)
**And** the display balance shows subscription + pack pool combined

**Given** free users can also buy packs (FR-25)
**When** a free-tier user creates a pack checkout
**Then** the endpoint accepts it (no active-subscription precondition applies to packs), `grant_credits` grants the credits into the 'pack' pool, and the user's tier is unchanged (free stays free); the free-tier pack-card rendering on /billing is the 5.5 surface [AMENDED 2026-08-10, John PM verdict — backend contract only; card rendering is 5.5; 5.1 F1 precedent]

**Given** the pack purchase receipt
**When** payment succeeds
**Then** a receipt email is sent (locale-aware, per Story 1.8)
**And** a success toast confirms "{n} credits added — pack credits never expire" on the /billing page — toast slot owned by the 5.6 polling bridge (Story 5.6 success state; copy contract recorded in D15, localized ar/fr/en, {n} latn per AD-8) [AMENDED 2026-08-10, John PM verdict — the toast fires from the 5.6 status flow, not 5.4; 5.1 F1 precedent]
